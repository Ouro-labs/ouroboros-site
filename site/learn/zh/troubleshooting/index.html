故障排查

先按症状找到对应的一节，然后照顺序走：先查什么、跑什么命令、期望看到什么。

1. 插件报 -32000，MCP 服务起不来

症状：Failed to reconnect to plugin:ouroboros:ouroboros: -32000

先查版本。这个启动失败在 0.51.1 修了，而且是那个版本发布说明里的头一条。在那之前，机器上已有的环境可能盖掉 [mcp] profile 需要的 mcp==2.0.0。修法是让随包发布的启动器走 uvx --isolated。

ooo update

期望结果：升到 0.51.1 或更新的版本。升完把 Claude Code 完全关掉再开。

这一节英文版和韩文版目前没有。如果你是从 AUR 之类的第三方源装的，先确认那边的版本号——第三方打包可能落后好几个版本。

2. ooo 命令不认识

先查两件事：ooo 只在 Claude Code 会话里能用，别在普通终端里敲；没登录也会失败，先在会话里 /login。

然后在普通终端里查插件状态：

claude plugin list

期望结果：ouroboros@ouroboros 显示 enabled。没有或是 disabled 就重装：

claude plugin install ouroboros@ouroboros --force

装完重开 Claude Code 会话，ooo help 应该能用。

3. 访谈能用，但 run 或 status 挂了

先查：插件加载了，但 Core 的 MCP 服务可能没连上。在 Claude Code 里用 /mcp 看 ouroboros 服务的状态。

在会话里按顺序跑：

ooo setup
ooo update

期望结果：MCP 服务重新注册。之后把 Claude Code 完全关掉再开。独立命令行安装的话，在普通终端里查 ouroboros mcp info 和 ouroboros status health。

4. 看着像卡住了

先查：后台跑的活本来就可能很久。先问状态，别先取消。

ooo status <session_id>

期望结果：显示当前阶段。确认确实没进展再用 ooo cancel 取消重跑。

5. auto 中断了怎么接着跑

ooo auto 在某个关卡或出错停下来时，输出里会留下 auto_session_id 和恢复命令：

ooo auto --resume <auto_session_id>

期望结果：同一个 auto 会话继续。ID 丢了就看下一节。

6. 窗口关了，会话还找得回来吗

找得回来。执行事件存在 EventStore 里，会话不会因为关窗口就没了。

ooo resume-session

期望结果：列出正在跑或暂停的会话，挑一个重新接上。

这一页对着当前源码和发布说明核过：-32000 那一节的依据是 v0.51.1 的发布说明（「shipped launchers now run uvx --isolated」）；resume-session、mcp info、status health 在 CLI 文档里；--resume 在 CLI 文档里查不到，但源码里实际存在（auto/resume_render.py 会直接打印这条命令）。文档里没有，不等于不存在。有对不上的地方，欢迎到 GitHub Issues 说一声。
