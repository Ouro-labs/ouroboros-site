# 설정 GUI 변경 검토와 되돌리기

Ouroboros 설정 GUI에서 설정을 편집할 때 이 안내를 사용하세요. 공개 제품 main [`592c667f`](https://github.com/Q00/ouroboros/tree/592c667f076c3dad7ef68d7844e91480d80135d0)의 저장 및 Undo 동작을 설명합니다. 호스트 플러그인, 공개 패키지, 사용 중인 서버 또는 CLI는 서로 다른 판본일 수 있으므로 이 내용을 적용하기 전에 설치된 버전의 도움말을 확인하세요.

## 설정을 바꾸기 전에

CLI 환경에서 `ouroboros config`를 실행하면 GUI가 열립니다. 환경에 따라 터미널 UI 또는 브라우저로 제공되는 화면이 열릴 수 있습니다. 변경하려는 호스트나 서버가 사용하는 기기, 사용자 계정, 설정 디렉터리와 같은 대상인지 확인하세요. 독립 CLI와 호스트가 실행하는 MCP 서버가 서로 다른 설정을 읽을 수 있습니다.

편집 전에 현재 값과 설정의 의미를 확인하세요. 일부 설정은 새 세션부터 적용되거나 MCP 서버 재연결이 필요합니다. 설정 저장만으로 실행 중인 호스트가 새 설정을 다시 읽었다고 볼 수는 없습니다.

## 저장하고 확인하기

1. 의도한 설정을 편집하고 **Save**를 선택합니다. GUI는 이 동작 전까지 편집 내용을 저장하지 않습니다. 바뀐 내용이 없으면 `No changes to save.`라고 표시합니다.
2. 결과를 읽습니다. 성공하면 상태 줄에 `Saved.`와 변경된 값의 요약이 표시됩니다. 백엔드 관련 설정을 바꾸면 변경 사항이 새 세션에 적용된다는 경고와 지금 적용하려면 MCP 서버를 재연결하라는 안내가 표시됩니다.
3. 같은 설정 환경에서 의도한 값이 반영됐는지 확인합니다. 호스트 서버에 적용해야 하는 변경이면 필요에 따라 해당 서버를 재연결하고 실제 도구/연결 상태를 확인하세요. 값이 저장됐다는 사실만으로 호스트가 새 설정을 읽었다고 단정할 수 없습니다.

GUI는 공유 설정 스키마에 따라 키 경로를 검증하고 YAML을 쓴 다음 설정 로더로 결과를 확인합니다. 기존 `config.yaml`이 있었다면 검증과 임시 백업 쓰기가 모두 성공한 뒤에야 기존 파일의 바이트를 `config.yaml.bak`으로 교체합니다. 따라서 GUI 저장이 성공하면 한 단계 Undo 스냅샷이 갱신됩니다. 이전 설정 파일이 없었다면 백업에 넣을 기존 파일 바이트도 없습니다.

## Save에서 오류가 표시되면

오류 전문을 읽으세요. 쓰기 또는 쓰기 후 검증 오류가 발생하면 GUI는 이전 설정 파일의 바이트를 복원하려고 합니다. 이전 파일이 없었다면 새로 만든 파일을 제거하려고 합니다. `Configuration rolled back.`로 시작하는 메시지는 이 복원 시도가 완료됐음을 알립니다. 그래도 오류 원인을 해결하기 전에는 다시 저장하지 마세요.

메시지에 `Configuration rollback also failed`가 있으면 현재 파일이 이전 상태인지 새 상태인지, 또는 유효한 설정인지 가정하지 마세요. 오류를 보존하고 추가 쓰기를 멈추세요. 올바른 사용자 설정 디렉터리에 있는 실제 설정 파일과 기존 `.bak`을 확인하고, 재시도하거나 Undo를 실행하기 전에 도움을 받으세요. 이 메시지는 복원 시도에서 별도의 I/O 오류가 발생했다는 뜻이지, 디스크에 어떤 바이트가 남았는지 알려 주지는 않습니다. GUI는 임시 백업 정리 오류를 무시하므로 정리 오류가 표시되지 않았다고 모든 파일 작업에 문제가 없었다고 볼 수도 없습니다.

키 경로나 중첩 섹션 오류는 파일 쓰기 단계 전에 거부됩니다. 검증 또는 저장 실패 시 Undo 스냅샷을 의도적으로 갱신하지는 않지만, 소스가 모든 가능한 하드웨어 오류·프로세스 종료·동시 쓰기를 복구하는 일반 파일시스템 트랜잭션을 제공하지는 않습니다. 실제 오류 메시지가 보장하는 범위를 넘어 롤백을 약속하지 마세요.

## Undo와 CLI `config set` 경로

`ouroboros config undo`는 먼저 두 파일이 있는지, 백업이 UTF-8인지 확인한 다음 백업 바이트를 `config.yaml`에 쓰고 설정 로더에 새 파일 검증을 요청합니다. 검증 성공 후에만 이전 설정 바이트를 `.bak`에 씁니다. 따라서 다시 Undo를 실행하면 변경을 다시 적용하는 동작이 됩니다. 검증에 실패하면 명령은 현재 설정 파일의 바이트를 복원하려고 한 뒤 중단합니다. Undo는 가장 최근에 바꾼 한 필드가 아니라 설정 파일 전체에 영향을 주므로 대상 디렉터리와 백업을 확인하세요.

단, Undo는 파일시스템 트랜잭션이 아닙니다. 백업 바이트를 검증하기 **전에** `config.yaml`에 먼저 씁니다. 검증 오류가 나면 이전 현재 파일 바이트로 다시 쓰려고 합니다. 검증이 성공한 뒤에는 그 이전 바이트를 `.bak`에 직접 씁니다. 어느 쓰기에서든 I/O 오류가 나면 그 쓰기 전체를 감싸는 완전한 롤백 처리가 없습니다. 특히 마지막 `.bak` 쓰기가 실패하면 설정은 이미 바뀌어 있고 백업 상태는 불확실할 수 있습니다. 오류, 중단, 성공 메시지 부재만으로 Undo가 두 파일을 변경하지 않았다고 판단할 수 없습니다.

main `592c667f`의 `ouroboros config set KEY VALUE`는 별도 쓰기 경로입니다. 키와 값을 검증한 다음 이후 설정 로더 검증을 감싸는 `try` 바깥에서 `_save_config`를 호출합니다. `_save_config`는 대상 파일에 직접 씁니다. 따라서 검증 단계의 롤백이 시작되기 전에 쓰기 오류가 날 수 있습니다. 쓰기 후 로더 검증이 실패하면 이전 바이트를 복원하려고 하지만, 그 복원 쓰기 자체는 별도로 보호되지 않으므로 I/O 오류가 나면 결과가 불확실할 수 있습니다. `config set`이 성공해도 GUI의 `config.yaml.bak` 스냅샷은 갱신되지 **않습니다**. 따라서 이후 Undo는 가장 최근 `config set` 변경을 취소하는 대신 이전의 성공한 GUI 백업을 복원할 수 있습니다. 이 명령은 자체 키/값 파싱과 event-store 경로 검사를 수행하므로 GUI의 일괄 저장 동작이 모두 동일하다고 가정하지 마세요.

Undo 또는 `config set`을 사용하기 전에 현재 `config.yaml`과 `config.yaml.bak`이 있다면 **둘 다** 별도의 접근 통제된 위치에 보존하세요. 두 파일에는 자격 증명이나 비공개 설정이 있을 수 있습니다. 두 작업 중 I/O 오류가 나거나, 작업이 예기치 않게 중단되거나, 결과가 불분명하면 곧바로 반복 실행하거나 추측으로 Undo를 추가 실행하지 마세요. 원본 파일과 오류를 보존하고 실제 설정 파일 및 백업을 확인한 뒤 어떤 버전이 유효한지 판단하여 복구를 선택하세요. 명령이 성공을 보고한 경우에만 정상 교환을 기대할 수 있습니다. 소스는 쓰기 오류, 프로세스 중단 또는 저장 장치 오류에서 복구를 보장하지 않습니다. 스크립트 방식으로 편집하려면 `config set`을 선택하기 전에 변경할 설정, 현재 값, 설치 판본 및 Undo 백업을 확인하세요.
