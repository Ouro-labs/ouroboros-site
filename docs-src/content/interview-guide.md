# Interview: 아이디어에서 합의된 목표까지

이 안내는 요구가 아직 모호하거나 완료 기준이 정해지지 않은 작업을 시작할 때 사용합니다. 목적은 질문을 많이 하는 것이 아니라, AI가 대신 정해 버리면 결과가 달라지는 결정을 당신과 확인하는 것입니다. 이미 검토된 Seed가 있거나 명확한 작은 수정이라면 [기존 Seed 실행](/docs/seed-guide/#run-reviewed-seed) 또는 일반 작업 요청으로 시작해도 됩니다.

**판본:** 제품 공개 `main` `592c667f076c3dad7ef68d7844e91480d80135d0`의 [interview skill](https://github.com/Q00/ouroboros/blob/592c667f076c3dad7ef68d7844e91480d80135d0/skills/interview/SKILL.md), [seed skill](https://github.com/Q00/ouroboros/blob/592c667f076c3dad7ef68d7844e91480d80135d0/skills/seed/SKILL.md), [인터뷰 MCP 도구](https://github.com/Q00/ouroboros/blob/592c667f076c3dad7ef68d7844e91480d80135d0/src/ouroboros/mcp/tools/authoring_handlers.py)를 대조했습니다. 공개 사이트의 기존 [Interview 장](https://ouroboros.page/learn/interview/)은 2026-08-14에 확인한 `0.51.5` / `d103058fe` 판본입니다. 그 할 일 앱 예제 흐름은 이어받되 현재 명령과 기능의 근거로 삼지 않습니다. `main`, PyPI release, 호스트 plugin과 실제 MCP 서버는 서로 같은 판본이라고 가정할 수 없습니다. 설치된 host·server가 다르면 실제 응답과 해당 버전 도움말을 우선하세요. 세부 조건은 [기존 인터뷰 참조](/docs/interview-detail/), [판본 및 확인 범위](/docs/version-guide/#version-scope)에 있습니다.

## 어디에 입력하나요?

`ooo`는 **지원되는 AI 코딩 호스트의 대화창**에 입력합니다. 예를 들어 Codex나 Claude Code에서 작업할 프로젝트 폴더를 열고 다음을 말합니다.

```text
ooo interview "오늘 할 일을 추가하고 완료 표시할 수 있는 간단한 웹앱을 만들고 싶다"
```

터미널 명령이 아닙니다. standalone CLI를 설치했다면 터미널에서는 별도 인터뷰 경로를 사용합니다.

```bash
ouroboros init start "오늘 할 일을 추가하고 완료 표시할 수 있는 간단한 웹앱"
```

설치 경로와 호스트 설정은 [첫 실행 안내](/docs/first-run-detail/), [호스트 설정](/docs/setup-host-detail/)을 보세요. `ooo` skill과 terminal의 `ouroboros` CLI는 설치 위치와 지원 기능이 다를 수 있습니다. `ouroboros --version`은 해당 실행 파일의 패키지 버전만 알려 줍니다. 호스트가 별도로 실행하는 MCP 서버의 버전까지 증명하지 않습니다.

새 프로젝트 폴더를 호스트에서 열어 두면 질문의 `cwd`가 실제로 어디를 가리키는지 확인하기 쉽습니다. 제품 인터뷰 도구는 저장소 분석을 직접 하지 않습니다. 저장소 질문에 답하기 위해 AI가 파일을 읽었다면, 그 확인 사실과 사용자의 결정을 구분해 알려 주세요. 프로젝트 폴더가 다르거나 권한이 없다면 코드를 읽었다고 가정하지 마세요.

## 무엇을 묻고, 어떤 응답을 받나요?

인터뷰는 대체로 한 번에 하나씩 질문하며, 목표·제약·완료 기준을 모읍니다. 질문 수와 순서는 요청에 따라 달라집니다. 예를 들어 “할 일 앱”이라고만 하면 저장 후 새로고침해도 남아야 하는지, 완료한 일을 삭제할지 남길지, 한 사람만 쓸지 등을 물을 수 있습니다.

이 예시의 답은 **설명용으로 만든 합성 대화**이며 실제 실행 transcript가 아닙니다.

| 예시 질문 | 사용자가 정할 내용 |
| --- | --- |
| “새로고침한 뒤에도 작업이 남아야 하나요?” | 저장 지속성 또는 임시 상태 |
| “완료한 작업은 삭제할까요, 목록에 남겨 표시할까요?” | 완료 처리 방법 |
| “이 앱은 한 사람이 한 기기에서 쓰나요?” | 사용자 범위와 동기화 제외 여부 |
| “완료됐다고 직접 확인할 수 있는 동작은 무엇인가요?” | 화면이나 테스트에서 관찰할 수용 기준 |

모르는 것은 모른다고 답하고 대안을 물어도 됩니다. 사용자의 답을 단순 선택지 이름으로 줄이지 말고 이유와 범위도 보존하세요. 호스트가 선택지를 제안하더라도 최종 결정은 사용자가 확인해야 합니다. 기존 프로젝트에서 확인할 수 있는 사실은 파일 경로 등 근거를 함께 보고하고, 추측을 사용자 요구로 섞지 마세요.

질문을 잘 이해하지 못했다면 질문에 답한 척하지 말고 쉬운 표현이나 예시를 요청하세요. 지원 호스트라면 `ooo idk <모르는 용어와 이미 아는 내용>`이 질문의 설명 수준을 맞추는 데 쓰일 수 있습니다. 이 기능은 질문을 답변으로 바꾸거나 요구사항 검증을 느슨하게 하는 기능이 아닙니다. `idk` skill은 제품 main에 있지만 공개 `0.59.9` 패키지에서 제공된다고 확인하지 않았습니다. 대안은 호스트에게 “같은 결정을 유지하면서 쉬운 말로 설명해 줘”라고 말하는 것입니다.

## 질문을 이어가고 끝내기

각 질문에 답한 다음 실제 인터뷰 응답을 확인하고 다음 질문에 답하세요. 호스트가 `session_id`를 보여 주면 그대로 보존합니다. MCP를 직접 연결하는 환경에서는 새 인터뷰에 `initial_context`, 이어가는 호출에 실제 `session_id`와 `answer`가 사용됩니다. 인터뷰가 완료되면 실제 응답의 `completed`, `ambiguity_score`, `seed_ready`와 정리된 목표를 확인하세요. 이 MCP 필드는 일반 사용자 화면에서 그대로 보인다고 보장되지 않습니다.

제품 skill은 `seed_ready` 표식만으로 끝났다고 선언하지 않고, 미해결 요구를 검토한 뒤 목표를 한 문장으로 다시 말해 사용자가 승인하는 단계를 둡니다. 목표가 틀렸거나 범위가 빠졌다면 바로 Seed를 만들지 말고 고쳐서 인터뷰에 반영하세요. 목표가 맞으면 다음 [Seed 안내](/docs/seed-guide/)로 갑니다. `ooo auto`는 질문·Seed·실행을 한 명령에 맡기는 다른 경로입니다. 첫 사용에서 질문마다 직접 판단하고 싶다면 이 페이지의 `ooo interview`를 쓰세요. Auto 경로는 [Auto 문서](/docs/auto-detail/)에 있습니다.

## 상황별 다음 행동

- **첫 질문이 나오지 않거나 연결 오류가 났어요.** 현재 호스트, 실제 프로젝트 폴더, 연결된 MCP 서버와 그 응답을 확인합니다. 오류가 재개 가능하다고 표시되면 새 세션을 만들기 전에 반환된 실제 `session_id`로 이어가세요. 반복 실패 시 [호스트 진단](/docs/diagnostics-detail/)과 [복구 안내](/docs/recovery-detail/)을 봅니다.
- **입력이 너무 길다는 응답을 받았어요.** 이를 사용자에게 그대로 묻는 질문으로 취급하지 않습니다. 원래 목표·제약·완료 기준을 잃지 않게 요약해 같은 실제 세션에서 이어가고, 그다음 질문을 확인합니다.
- **OpenCode plugin이 위임 영수증을 반환했어요.** `delegated_to_subagent`와 같은 접수 상태만으로 인터뷰 결과가 나온 것은 아닙니다. Task pane의 실제 결과와 실제 `session_id`를 확인하세요.
- **완료 여부가 불분명해요.** `seed_ready` 또는 낮은 모호도 점수는 실제 생성된 Seed, 사용자 승인, 실행 성공을 뜻하지 않습니다. 인터뷰 요약과 미해결 질문을 읽고 필요한 결정을 보충하세요.
- **인터뷰를 진행할 필요가 없어요.** 목표·제약·검증 가능한 완료 기준이 이미 합의됐다면 Seed skill은 같은 대화의 합의된 내용을 바로 Seed로 만들 수 있습니다. 누락한 조건을 AI가 만들어 채우면 안 됩니다.

질문·응답·재개·참조 cues·보정 전달 등 세부 입력은 [인터뷰 MCP 색인](/docs/mcp-reference-detail/#ouroboros_interview), [인터뷰의 고정판 상세](/docs/interview-detail/)를 참고하세요. 인터뷰가 모델을 호출하는 경우 시간과 provider 비용이 들 수 있습니다. 이 문서 작성에서는 실제 host 대화, 인증, 모델 호출, MCP 연결 또는 세션 재개를 실행하지 않았습니다. 표의 질문과 응답은 설명용 합성 예시입니다.
